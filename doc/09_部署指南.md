# 09 部署指南

> 本文覆盖三种部署形态：本地源码运行（开发调试）、Docker Compose 一键部署（演示/自托管）、生产部署要点（检查清单）。

## 一、部署架构与端口

系统由 3 个自研组件 + 2 个中间件组成，典型部署拓扑：

```
用户浏览器 ──HTTP──▶ web (:8080)
                      │  /api/* 反向代理（Authorization → Grpc-Metadata-Authorization）
                      ▼
                   gateway (:8888)  REST → gRPC
                      │
                      ▼
                   cloud (:8081)    业务核心
                      │
            ┌─────────┼─────────┐
            ▼         ▼         ▼
         MySQL 8   Redis 7   本地磁盘/挂载卷
```

| 组件 | 默认端口 | 说明 | 是否对外暴露 |
| ---- | -------- | ---- | ------------ |
| cloud | 8081 | gRPC 业务服务 | ❌ 仅内网 |
| gateway | 8888 | REST API 入口 | ✅ |
| web | 8080 | 演示前端 + API 反代 | ✅（可选） |
| MySQL | 3306 | 元数据存储 | ❌ |
| Redis | 6379 | 秒传索引 / 分片状态 / 分享缓存 | ❌ |

## 二、本地部署（源码运行）

适用于开发调试。完整步骤见根 [README.md](../README.md) 的「快速开始」，此处为速览：

### 1. 环境要求

- Go 1.25+
- MySQL 8.x、Redis 7.x（本机或可达的远程实例）

### 2. 初始化数据库

只需建库，表结构由 ent 在服务启动时自动创建：

```sql
CREATE DATABASE `cloud` DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 3. 修改配置

编辑 `cloud/etc/storage.yaml`，确认 MySQL / Redis 连接信息（全部键位说明见 [10_配置说明.md](10_配置说明.md)）。

### 4. 按顺序启动（三个终端）

```bash
# 终端 1：核心 RPC 服务
cd cloud
go run main.go -f etc/storage.yaml

# 终端 2：HTTP 网关
cd gateway
go run gateway.go -f gateway.yaml

# 终端 3：Web 前端（可选）
cd web
go run server.go
```

### 5. 验证

```bash
# 注册
curl -X POST http://127.0.0.1:8888/user/register \
  -H "Content-Type: application/json" \
  -d '{"account":"test","password":"123456","nickname":"测试用户"}'

# 登录拿 token
curl -X POST http://127.0.0.1:8888/user/loginByAccount \
  -H "Content-Type: application/json" \
  -d '{"account":"test","password":"123456"}'
```

或直接访问 http://127.0.0.1:8080/index.html 使用 Web 界面。

## 三、Docker Compose 一键部署

适用于演示环境或单机自托管。**要求**：Docker 20.10+ 及 compose 插件（`docker compose` 子命令可用）。

### 1. 启动

在仓库根目录执行：

```bash
docker compose up -d --build
```

首次构建需要拉取 `golang:1.25-alpine` 基础镜像并编译三个组件，视网络情况需要几分钟。编排内容：

| 服务 | 说明 |
| ---- | ---- |
| mysql | MySQL 8，utf8mb4，自动创建 `cloud` 库，数据持久化在 `mysql-data` 卷 |
| redis | Redis 7，数据持久化在 `redis-data` 卷 |
| cloud | 核心服务，等 MySQL/Redis 健康检查通过后启动，物理文件存 `storage-data` 卷 |
| gateway | 网关，对外暴露 `:8888` |
| web | 前端，对外暴露 `:8080` |

容器版配置位于 `deploy/` 目录（与本地配置的差异：MySQL/Redis 用服务名互连、存储指向挂载卷、`Mode: prod`），通过只读挂载注入容器，**改完配置需重启对应容器生效**。

### 2. 访问

- Web 界面：http://localhost:8080
- REST API：http://localhost:8888（如 `POST /user/register`）

### 3. 常用运维命令

```bash
docker compose ps                # 查看各服务状态
docker compose logs -f cloud     # 跟踪核心服务日志
docker compose restart gateway   # 重启单个服务
docker compose down              # 停止并移除容器（保留数据卷）
docker compose down -v           # 停止并删除数据卷（⚠ 数据库与已上传文件将全部丢失）
```

### 4. 数据持久化位置

三个命名卷：`mysql-data`（元数据）、`redis-data`（缓存）、`storage-data`（物理文件）。
容器内存储路径为 `/data/cloud_storage`（见 `deploy/cloud/storage.yaml` 的 `Storage.Local.RootDir`）。

## 四、生产部署检查清单

上线前逐项确认：

- [ ] **服务模式**：`Mode: prod`（dev 模式会在启动时执行存量数据迁移，prod 不会）
- [ ] **MySQL**：不使用 root 账号，改为最小权限业务账号 + 强密码；不对外网暴露 3306
- [ ] **Redis**：设置 `Password`，仅内网可达
- [ ] **JWT Secret**：更换为 32 字符以上随机值（生成：`openssl rand -hex 32`），泄露即全量 token 失效重置
- [ ] **SQL 调试**：`MySQL.Debug: false`（生产打印 SQL 会拖慢性能并泄露数据）
- [ ] **端口收敛**：仅 gateway（8888）和按需的 web（8080）对外，8081/3306/6379 全部内网
- [ ] **HTTPS**：建议在 gateway/web 前加 Nginx/Caddy 终结 TLS，并限制上传体积（`client_max_body_size`）
- [ ] **存储与备份**：确认 `Storage.Local.RootDir` 指向的数据盘容量，制定 MySQL 备份（mysqldump / xtrabackup）与文件目录备份策略
- [ ] **日志**：go-zero 日志输出到 stdout，由容器运行时/ systemd 收集轮转
- [ ] **重启策略**：容器场景已内置 `restart: unless-stopped`；裸机场景建议 systemd 托管

## 五、常见问题

| 现象 | 排查 |
| ---- | ---- |
| cloud 启动报数据库连接失败 | 检查 MySQL 地址/密码/库是否已创建；compose 场景确认 mysql 健康检查通过 |
| 网关 502 / 接口全挂 | cloud 未就绪或重启中，gateway 会自动恢复，稍后重试 |
| Web 页面能开但登录失败 | web 的 `-api` 指向的网关地址不对（本地默认 `http://localhost:8888`） |
| 上传大文件失败 | 先检查网关前的 Nginx `client_max_body_size`；分片上传见 [07_P5_高级能力设计.md](07_P5_高级能力设计.md) |
| 容器改了配置不生效 | `deploy/` 配置是只读挂载，改完执行 `docker compose restart <服务>` |
