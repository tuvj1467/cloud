## 二、项目概览

**ONE CLOUD** 是一个生产级私有云对象存储服务：go-zero 微服务（gRPC RPC + HTTP 网关）+
ent ORM + MySQL（元数据）+ Redis（缓存/计数）+ 可切换存储后端（本地磁盘 / MinIO / S3 兼容）。
前端为 Vue 3 无构建链单页应用（`web/`，由 Go 静态服务器托管并反代 API）。

能力边界（详见根 README「核心特性」）：桶管理（配额/乐观锁）、上传（直传≤5MB / 分片断点续传）、
秒传（MD5 索引）、下载（一元/流式/预签名）、分享（read/download 权限、有效期/次数、匿名流式）、
回收站（30 天自动清理）、缩略图、用量统计与趋势、管理后台（角色/禁用/审计/强制删除）、
限流与登录锁定。**未实现**：图片处理（缩放/水印）、服务端加密、多副本。

三个可部署单元：
- `cloud`（gRPC :8081）—— 全部业务逻辑，唯一写 DB/Redis/存储的组件
- `gateway`（HTTP :8888）—— 纯协议转换 REST↔gRPC，无业务逻辑
- `web`（HTTP :8080）—— 静态前端 + `/api` 反代（Authorization 头桥接为 gRPC metadata）

## 三、环境搭建与本地运行

### 3.1 前置依赖

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Go | 1.25+ | 三个模块编译（cloud / gateway / web 各有 go.mod） |
| MySQL | 8.x | 元数据。建库：`CREATE DATABASE cloud DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_unicode_ci;` |
| Redis | 7.x | **可选**。未部署时服务照常启动，走降级路径（见 §5.7） |
| MinIO | 任意近期 RELEASE | **可选**。默认 local 磁盘驱动；S3 约束见 §6 |
| protoc + protoc-gen-go + protoc-gen-go-grpc + protoc-gen-validate | 与生成文件头版本一致 | 仅改 proto 时需要 |
| ent 代码生成 | go.mod 内版本（`go generate` 自动拉取） | 仅改 schema 时需要 |

> Go 插件二进制若缺失：`go install google.golang.org/protobuf/cmd/protoc-gen-go@latest` 等，
> 版本务必对齐已生成文件头注释中的版本（当前 protoc-gen-go v1.36.11 / gen-go-grpc v1.6.1）。

### 3.2 本地启动（开发形态）

```bash
# 1. 配置 cloud/etc/storage.yaml（MySQL 连接；Redis 缺省可注释）
# 2. 三件套（三个终端分别执行）
cd cloud   && go run main.go -f etc/storage.yaml      # dev 模式自动建表+存量迁移，监听 :8081
cd gateway && go run gateway.go -f gateway.yaml        # 监听 :8888
cd web     && go run server.go                          # 监听 :8080（-port 可改）
# 3. 浏览器打开 http://127.0.0.1:8080/index.html
```

dev 配置已启用限流（QPS 10 / Burst 20），自动化脚本请节流或临时关闭。

### 3.3 验证体系（改动后必跑）

```bash
cd cloud && go build ./... && go vet ./... && go test ./... -count=1   # 9 个测试包（repository 为 DB_IT 门控集成包）
python scripts/smoke_e2e.py                                            # 35 项端到端断言（需 cloud+gateway 已启动）
```

- 单测覆盖：JWT（含 alg=none 拒绝）、限流（身份键/溢出桶）、存储驱动（本地 Put/合并/路径安全）、
  验证码（日配额）、登录锁定（含 Redis 故障降级）、passwd/util/logic 纯函数。
- E2E 覆盖：认证/桶/直传/秒传/分片全周期/重复 complete 门闩/流式/分享权限/回收站闭环/
  统计/预签名回落/锁定/429。无 Redis 亦可跑（顺带验证降级路径）。

- CI：`.github/workflows/ci.yml`——三模块 build+vet+test 矩阵 + 三镜像 docker build。
  MinIO 冒烟（`MINIO_SMOKE=1` 门控）需真实服务，CI 自动跳过。

`docker compose up -d --build`（详见 doc/09）。生产前**必须**过 doc/09 的检查清单：

## 四、代码导读

### 4.1 模块地图（请求自上而下流经）

```
浏览器 ──HTTP──▶ web/server.go(反代+Authorization桥接)
        ──HTTP──▶ gateway/gateway.go(REST→gRPC，路由在 gateway.yaml)
        ──gRPC──▶ cloud/main.go(拦截器链：Recovery→限流→JWT→用户状态注入)
                  └▶ internal/server/(纯委托层，勿写逻辑)
                     └▶ internal/logic/(业务逻辑，按 user/file/bucket 分包)
                        ├▶ internal/repository/(唯一 DB 访问层，ent 客户端)
                        ├▶ internal/pkg/cache/(唯一 Redis 访问层，nil 安全)
                        └▶ internal/pkg/storage/(唯一物理存储访问层，Driver 接口)
```

**分层纪律（务必遵守）**：logic 之外不得碰 ent 客户端；cache 包统一做 nil 安全
（Redis 未配置时返回可识别错误而非 panic，见 `pkg/cache` 包注释）；物理文件一律经
`storage.Driver`，禁止 logic 直接 os/io。

### 4.2 三条核心链路（先读这三个，其余触类旁通）

1. **直传上传** `logic/file/upload_file_logic.go`
   校验→秒传检查（Redis 索引→DB 兜底）→**先原子扣桶配额**→写物理/建记录→写秒传索引。
   注意「配额优先」顺序与统一 rollback（§5.1）。
2. **分片上传** `logic/file/init_multipart_upload_logic.go` → `upload_part_logic.go` →
   `complete_multipart_upload_logic.go`
   DB `file_parts` 记录是完整性的**唯一基准**（Redis parts 只是加速）；
   Complete 入口有 uploaded→merged 一次性状态迁移做**合并权门闩**（§5.2）。
3. **匿名分享下载** `logic/file/share_helper.go`（公共加载）→
   `download_by_share_logic.go` / `download_by_share_stream_logic.go`
   计数走 Redis Lua「校验+递增+TTL 续期」，Redis 故障降级 DB 兜底（§5.7）。

## 五、必须掌握的设计不变式（改代码前先读）

### 5.1 配额优先记账
上传/分片合并都是**先原子扣桶容量**（`TryIncUsedSize` 单条 UPDATE），后写物理/记录；
后续任一步失败走统一 rollback **补偿性归还**。不要改回「先建记录后扣配额」——
那会在中间崩溃时留下永久配额漂移。

### 5.2 Complete 合并权门闩
`file_parts` 的 uploaded→merged 一次性状态迁移保证同一 upload_id 并发 Complete 只有
一次成功，杜绝重复合并/重复扣配额。所有失败路径必须恢复 uploaded（`RestoreUploaded`）；
新加的失败分支记得接入 `rollback`。

### 5.3 秒传共享物理路径
多个 File 记录可指向同一物理文件（跨桶/改名秒传）。因此**任何物理删除必须走**
`repository.DeletePhysicalIfUnshared`（引用计数守卫），直接 `Storage.Delete` 会删掉
别人的文件。秒传命中要求 size 一致（MD5 相同但 size 不同视为碰撞，走完整上传）。

### 5.4 限流身份键不可伪造
限流键 = JWT 验签后的 user_id；匿名 = 网关转发的 XFF 首跳（可伪造，仅尽力分桶）。
**绝不能**把 Authorization 原文当键（可随机化绕过）。桶有 10 万上限与 30 分钟空闲回收。

### 5.5 登录锁定键是用户 ID
手机/邮箱注册用户 username 为 NULL——用 username 作键会让全体该类用户共享计数桶
（锁定失效 + 可互相锁死）。锁定的 fail 路径统一走 `loginWithLookup`。

### 5.6 会话版本化（P24）
`users.token_version`：重置密码 / 禁用 / **角色变更**都会 +1，JWT 内嵌 ver 与 DB 比对，
落后即踢。给"应立即失效用户所有会话"的新功能复用 `AddTokenVersion(1)`。

### 5.7 降级语义矩阵（Redis 不可用时）

| 能力 | 行为 |
| --- | --- |
| 秒传索引 | 跳过 Redis，直接查 DB（`repository.GetByMD5`） |
| 登录锁定 | 进程内计数兜底（多实例下阈值放宽为 阈值×实例数），限频告警 |
| 分享下载计数 | DB 兜底：查记录校验 max_count 后原子自增；DB 也不可用则放行并记失计 |
| 分片状态 | DB 是基准，Redis parts 仅加速（命中会回查修复 DB） |
| 验证码 | 返回明确「服务不可用」错误（该能力依赖 Redis，无降级） |

### 5.8 其他不变式
- 匿名接口只信任网关注入的 metadata（`gateway-*` 前缀）；XFF 可伪造，审计仅作参考。
- 物理文件名/路径必须过 `ValidSuffix` + `ValidStorageID` + `SafeJoin`（防穿越）。
- 回收站文件：详情/下载/复制/缩略图/分享**全链路**按不存在处理（新增文件类接口记得过滤 `DeletedAt`）。
- 内部错误一律 `response.ErrInternal`（细节只进日志）；参数校验类文案可透传。

## 六、陷阱清单（交接最易踩的坑）

1. **两份网关路由必须同步**：`gateway/gateway.yaml` 与 `deploy/gateway/gateway.yaml`
   是手工维护的两份（后者仅 gRPC target 不同）。改路由**两份都要改**，E2E 不会替你发现漏改。
2. **网关必须在 `gateway/` 目录下启动**：`protoset.pb` 按相对路径加载，在其他 CWD 执行
   `gateway.exe -f .../gateway.yaml` 会 fatal 退出（实测 2026-10-31）。三件套的启动命令
   都默认各自目录为工作目录（配置同样按相对路径解析）。
3. **改 proto 的完整再生成链**（在 `cloud/proto/` 下执行 `generate_all.cmd` 三步）：
   消息+validate → gRPC 桩 → **gateway/protoset.pb**（网关运行时靠它，漏了路由直接 404/405）。
   新增匿名接口还要同步 `jwt_middleware.isPublicMethod` 白名单（流式方法另有流式拦截器）。
4. **`internal/server/*` 标注 DO NOT EDIT 但已手工维护**——文件头有警示。重跑 goctl 会
   **覆盖丢失手写方法**（如 Admin*）。新增 RPC 时手工补委托方法。
5. **ent schema 改后**：`cd cloud/ent && go generate ./...`。dev 模式启动自动迁移；
   **prod 模式不迁移**，需自行执行 schema 变更。
6. **前端直传阈值与后端联动**：`DIRECT_MAX`（UploadPanel.js）≤ 后端
   `Storage.DirectUploadSize`（默认 5MB），>5MB 前端自动走分片。改其一必须同步另一个，
   否则用户看到「超过直传上限」报错。
7. **MinIO/S3 分片硬约束**：除最后一片外 ≥5MiB。后端在 init 阶段强制（仅 minio 驱动）；
   前端默认 5MB 切片合规，自研客户端注意。
8. **多实例部署必须配 `Snowflake.WorkerId`**（0-1023 互不相同），否则主键冲突。
9. **仓库里的非源码内容勿参考**：`.superpowers/sdd/snapshots/`（50+ 份历史文件快照）、
   `cloud/.entc/`（生成器临时文件）、各目录 `*.exe`（本地构建产物，已 gitignore）。
   判断代码真伪永远以 git 跟踪的文件为准。
10. **web/js 是无构建链 ES Module**：`index.html` 直接 `<script type="module">`，
   组件用全局 Vue（`web/js/vendor/vue.global.prod.js`，版本见文件头）。加依赖=放 vendor
   并在 README 记录版本，没有打包器兜底语法错误——改完 `node --check` 验证。
11. **错误码是契约**：前端 `api.js errText` 表与 `cloud/internal/pkg/response/codes.go`
    一一对应，加错误码两边同步。

## 八、部署与运维要点

- **部署形态**：docker-compose（mysql/redis/cloud/gateway/web + 可选 minio profile），
  镜像 tag 已固定（MinIO 除外，生产须固定 RELEASE tag）；cloud 有 TCP healthcheck，
  gateway 依赖其健康。
- **配置注入**：deploy 配置在 `deploy/cloud/storage.yaml`；JWT Secret 推荐 `${JWT_SECRET}`
  环境变量注入，prod 模式对演示值/短密钥**拒绝启动**（见 `service_context.go`）。
- **日志**：关键路径均有结构化日志（logx，key=value）；验证码在非 dev 模式自动脱码；
  MySQL Debug 生产必须 false。
- **数据清理**：`pkg/cleanup` 每 12h——回收站 30 天、分享审计 90 天、.tmp 48h（同步清
  Redis 上传状态）。MinIO 孤儿 multipart 由驱动每 12h 对账中止（Initiated >48h）。

## 九、已知技术债与建议路线（按优先级）

1. **FileList.js（约 710 行）拆分**：列表/趋势/回收站/我的分享/访问审计/预览六个弹层交织，
   内部函数注释率低。建议先补浏览器 GUI 冒烟再动。
2. **camel/snake 契约收敛**：网关 JSON 字段名与 proto 双命名并存，前端散布 6 处兼容垫片。
   一次性收敛需动全部 46 个端点（口径：service.proto 的 46 个 rpc = 网关 46 条映射）契约，适合独立批次。
3. **logic 层单测覆盖**：目前测的是纯函数与 pkg；分片/分享/配额的 logic 层用例（需 DB/Redis
   或 mock）建议按「分片→分享→配额」分批补。
5. **web/js 四件套文件头与 FileList 内部注释**（部分已补，历史弹层逻辑仍偏薄）。
5. 上传直传仍以 proto bytes 承载（≤5MB 已限幅，风险受控）；如需彻底流式化是 proto 大改。
6. MinIO 驱动 `uploads` 映射的条目级 TTL 未做（对账已兜底孤儿，条目自身生命周期靠
   Complete/Abort/对账消费）。
