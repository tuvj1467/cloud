## 二、分层职责

### 2.1 Gateway 层（`gateway/`）

- 职责：HTTP REST 请求 → gRPC 调用，响应统一封装
- 不含业务逻辑，仅做协议转换与路由
- 配置驱动：`gateway.yaml` 描述 upstream 与 mapping

### 2.2 Server 层（`internal/server/`）

- 职责：实现 gRPC service 接口，做请求转发到 logic
- 不含业务逻辑，仅做参数透传与响应包装
- 每个服务一个文件：`file_server.go` / `bucket_server.go` / `user_server.go`

### 2.3 Logic 层（`internal/logic/`）

- 职责：核心业务编排
- 每个 RPC 方法对应一个 `xxx_logic.go`
- 依赖注入：通过 `svc.ServiceContext` 获取 repository、storage driver、redis
- 规范：
  - 入参先 `validate`
  - 鉴权信息从 context 取（`jwt.GetUserIdFromCtx`）
  - 业务校验、调用 repository、调用 storage driver
  - 统一通过 `response.Success` / `response.Err` 返回

### 2.4 Repository 层（`internal/repository/`）

- 职责：数据持久化访问，封装 ent 操作
- 每个实体一个文件：`file.go` / `bucket.go` / `user.go`
- 不含业务规则，仅 CRUD + 查询
- 事务由 logic 层发起，repository 接收 ctx 传递

### 2.5 Storage 驱动层（`internal/pkg/storage/`）— 新增

- 职责：抽象物理存储操作（上传/下载/删除/分片）
- 接口定义 `StorageDriver`，多个实现：
  - `local_driver.go`：本地磁盘（开发默认）
  - `minio_driver.go`：MinIO/S3 兼容（生产推荐）
- logic 层只依赖接口，由 `ServiceContext` 注入具体实现

### 2.6 基础设施层（`internal/pkg/`）

| 包 | 职责 |
| -- | ---- |
| `cache` | Redis 连接与封装 |
| `database` | MySQL 连接与 DSN 拼接 |
| `jwt` | Token 生成、解析、context 注入 |
| `snowId` | 雪花 ID 生成（单例） |
| `response` | gRPC 统一响应封装 |
| `util` | MD5、文件类型检测等工具 |
| `storage` | 存储驱动抽象与实现（新增） |

## 三、调用链路示例（上传文件）

```
客户端
  │ POST /file/upload (multipart/form-data 或 base64)
  ▼
Gateway (gateway.go)
  │ 转 gRPC: storage.File/UploadFile
  ▼
FileServer.UploadFile  (internal/server/file/file_server.go)
  │
  ▼
UploadFileLogic.UploadFile  (internal/logic/file/upload_file_logic.go)
  │ 1. validate 入参
  │ 2. 从 ctx 取 user_id
  │ 3. 计算 MD5
  │ 4. 查 Redis 秒传索引（命中则直接返回已有 file_id）
  │ 5. 获取/创建默认桶，校验容量
  │ 6. 调用 StorageDriver.Put(ctx, path, content)
  │ 7. 调用 FileRepository.Create 写库（含 bucket_id/user_id/md5）
  │ 8. 写 Redis 秒传索引  md5 -> file_id
  │ 9. 更新桶 used_size（事务 + 乐观锁）
  ▼
FileRepository.Create  (internal/repository/file.go)
  │ ent.File.Create()
  ▼
MySQL
```

## 四、服务上下文（依赖注入）

`svc.ServiceContext` 扩展后应包含：

| 字段 | 类型 | 来源 |
| ---- | ---- | ---- |
| Config | config.Config | 配置文件 |
| Db | *sql.DB | database 包 |
| EntClient | *ent.Client | ent.Open |
| Redis | *redis.Client | cache 包 |
| Snowflake | *snowId.Snowflake | snowId 包 |
| Storage | storage.Driver | storage 包（新增） |

初始化顺序：Config → MySQL/Ent → Redis → Snowflake → StorageDriver。

## 五、配置结构扩展

`config.Config` 新增：

```go
type Config struct {
    zrpc.RpcServerConf
    MySQL DB
    Redis RedisConf
    Storage StorageConf   // 新增
    JWT    JWTConf        // 新增
}

type StorageConf struct {
    Driver   string `json:",default=local"`   // local | minio | s3
    Local    LocalStorageConf
    Minio    MinioConf
}

type LocalStorageConf struct {
    RootDir string `json:",default=./cloud_storage"`
}

type MinioConf struct {
    Endpoint  string
    AccessKey string
    SecretKey string
    Bucket    string
    UseSSL    bool
}

type JWTConf struct {
    Secret string
    Expire int64  // 秒
}
```

## 六、错误码规范

复用 `internal/types/error.go`，按段扩展：

| 段 | 范围 | 含义 |
| -- | ---- | ---- |
| 0 | 0 | 成功 |
| 1xxxx | 10001-19999 | 通用错误（参数/内部/未找到） |
| 2xxxx | 20001-29999 | 业务错误（用户/文件/桶） |
| 3xxxx | 30001-39999 | 存储错误（驱动/容量/分片） |

## 七、并发与一致性策略

1. **桶容量扣减**：事务内 `SELECT ... FOR UPDATE` + 乐观锁 `version` 校验
2. **秒传索引**：Redis `SETNX`，key = `md5:{md5}`，value = `file_id`
3. **分片上传状态**：Redis Hash 存储已上传分片号，key = `upload:{upload_id}`
4. **文件删除**：先删 DB（软删或硬删），再异步删物理文件（避免主链路阻塞）
