# 13 夜间自主开发路线图（P16+）

> **用途**：本文件供定时拉起的自主开发会话执行。每个会话按顺序认领**第一个未完成条目**，只做一个条目，做完即提交。
>
> **硬性守则（每轮必读）**：
> 1. 当前本地时间 ≥ 07:50 → 本轮只做收尾检查（`git status` 干净、服务已停、无测试残留数据），不再开新条目
> 2. 每轮只做一个条目；完成或阻塞都要在本文件勾选状态，并在 `.superpowers/sdd/progress.md` 追加一行
> 3. 提交前必须 `cd cloud && go build ./... && go vet ./... && go test ./...` 全绿；前端改动逐文件 `node --input-type=module --check < 文件`
> 4. 不 push、不动 git 历史、不 force 任何操作；每条目独立提交，格式 `feat: Pxx-Mn 条目名`
> 5. 冒烟用的服务进程按 PID 关闭、测试数据（用户/桶/文件/分享）与测试产物清理
> 6. 阻塞（外部条件不满足、需人工决策）→ 在本文件标注 `⛔ 阻塞原因` 并结束本轮，不硬闯
> 7. 不引入新的重依赖（M3 的 `golang.org/x/image` 除外）；遵循既有架构约束（logic 禁止直连 svcCtx.Redis、storage 层收口路径安全、proto 只做向后兼容新增）

## M2：流式下载（gRPC server-streaming）

- [ ] **状态：待执行**
- proto：`service.proto` File 服务加 `rpc DownloadStream(DownloadFileRequest) returns (stream DownloadChunk);`；`file.proto` 加 `message DownloadChunk { bytes data = 1; int64 sent = 2; int64 total = 3; }`
- logic：权限/归属校验复用 `download_file_logic`；`Storage.Get` 后 64KB 分块 `stream.Send`；结束前发总量校验块
- **网关风险与决策树**（先验证再写业务）：用最小 protoset + curl 实测 go-zero gateway 对 server-streaming 的 REST 转发是否可用
  - 可用 → 加路由 `POST /file/download_stream`，前端大文件（>50MB）下载改走 `fetch` + `response.body.getReader()` 流式拼接 blob
  - 不可用 → **本条降级关闭**：在 doc/13 标注「网关不支持流式转发，预签名直连已是既定大文件方案」，提交文档说明即算完成
- 验收（若走通）：10MB 文件经 `/file/download_stream` 下载内容一致；`go run` 进程内存无明显整文件缓冲
