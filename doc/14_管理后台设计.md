# 14 管理后台设计（已实现）

> **状态**：✅ 已实现（2026-09-13，P18~P20 三批落地）——期 1（role/disabled + 拦截器状态注入 + 用户列表/改角色/禁用）、期 2（AdminPanel 前端 + 全局统计）、期 3（管理操作审计表 admin_audit_logs + AdminPurgeFile 强制删除 + 审计展示）全部完成。与设计的差异：禁用用户的 token 失效采用「拦截器 60s 状态缓存」而非 token 黑名单表（实现更简，禁用最迟 60s 生效，已可接受）。P24 会话版本化补记（2026-10-05）：重置密码与**禁用**均 bump `token_version` 立即踢出既有 token；**角色变更同样 bump**——被降权的 admin 不再能凭旧 token 在 60s 缓存窗口内行使管理权限。

## 一、目标

为运营者提供租户视角的管理能力：用户治理、全局存储概览、内容合规处置。不改变既有用户侧功能。

## 二、角色模型

- `users` 表新增 `role` 字段（enum：`user` 默认 / `admin`），加索引；
- 鉴权：JWT Claims 增加 `role`（旧 token 无 role 视为 user，兼容存量）；管理接口在独立拦截器中校验 `role == admin`，非管理员一律 `403`；
- 首个管理员通过 SQL 手工提升（`UPDATE users SET role='admin' WHERE username=?`），不做自助注册管理员。

## 三、管理 API（均挂 `/admin/*` 前缀，需 admin 角色）

> 现行接口以 service.proto 与网关映射为准（下表 2026-11-02 同步；设计期路径 `/admin/users/:id/role` 等已演进为现行形态）。

| 接口 | 方法 | 说明 |
|------|------|------|
| /admin/users | GET | 用户列表（分页/关键词搜索 username/nickname/phone，含角色、禁用状态、文件数/容量聚合） |
| /admin/users/role | POST | 设置角色（user/admin；禁改自己；变更即 bump token_version 踢出旧会话） |
| /admin/users/disabled | POST | 禁用/启用（禁用即 bump token_version，既有 token 立即被拒） |
| /admin/stats | GET | 全局统计（用户数/文件数/总容量） |
| /admin/share-access-logs | GET | 全局分享访问/下载审计（倒序分页） |
| /admin/files/purge | POST | 管理员强制彻底删除任意文件（绕过归属校验，写操作审计） |
| /admin/op-logs | GET | 管理操作审计查询（改角色/禁用/强制删除） |

- 复用项：分页/错误码/审计表（share_access_logs 扩展 actor 维度）沿用现有体系；
- 审计：管理操作全部写入新表 `admin_audit_logs`（admin_id/action/target/created_at）。

## 四、前端

- `web/` 新增管理入口（仅 admin 角色登录后可见）：用户管理表格（搜索/改角色/禁用）+ 全局统计卡（复用统计卡与趋势图组件）；
- 组件化沿用现有 `web/js/components/*` 模式，无构建链。

## 五、分期

1. 期 1：role 字段 + admin 拦截器 + 用户列表/禁用；
2. 期 2：全局统计 + 强制删除；
3. 期 3：前端管理页 + 操作审计展示。

## 六、风险

- disabled 用户存量 token 失效需要拦截器每次查库（性能）或短 token + 黑名单表（推荐后者：`token_blacklist`，禁用时写入该用户所有未过期 token 摘要）；
- 管理接口限流建议独立更严阈值（复用 RateLimit 体系，按 IP）。
