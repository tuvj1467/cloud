## 执行顺序与依赖

```
P1（修复）─▶ P2（基础设施）─▶ P3（桶服务）─▶ P4（文件补全）─▶ P5（高级能力）
                                                          └▶ P6（加固）
```

- P1 / P2 可串行快速完成
- P3 必须先于 P4（文件操作依赖桶）
- P5 依赖 P4 完成的上传链路
- P6 可与 P5 部分并行

## 验收方式

每阶段完成后：

1. `cd cloud && go build ./...` 编译通过
2. 启动 `storage.rpc` 与 `gateway`，无报错
3. 用 grpcurl 或 Postman 验证本阶段接口
4. 同步更新对应 md 文档（workspace 规则）
