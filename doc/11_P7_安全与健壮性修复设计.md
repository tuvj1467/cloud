## 三、验证码组件

### 3.1 key 规范（唯一定义处）

| key | 值 | TTL | 用途 |
|-----|-----|-----|------|
| `sms_code:{contact}:{type}` | 6 位数字码 | 5 分钟 | 验证码本体；`type` 取 `proto/user.proto` 的 SmsType 枚举（登录/注册/重置密码等），实现时以 proto 为准 |
| `sms_code_limit:{contact}:{type}` | 1 | 60 秒 | 发送频率限制（SETNX 抢占） |
| `sms_code_fail:{contact}:{type}` | 失败次数 | 5 分钟 | 失败计数，达 5 次作废验证码 |

### 3.2 接口

```go
type KV interface {
    Get(ctx, key) (string, error)              // 未命中返回 ErrNotFound
    Set(ctx, key, val string, ttl time.Duration) error
    SetNX(ctx, key, val string, ttl time.Duration) (bool, error)
    Del(ctx, key) error
    Incr(ctx, key string, ttl time.Duration) (int64, error)  // 首次自增时设置 TTL
}

type Sender interface {
    Send(ctx context.Context, contact string, typ int, code string) error
}

type Service struct{ kv KV; sender Sender }
func NewService(kv KV, sender Sender) *Service
func (s *Service) Send(ctx, contact string, typ int) error
func (s *Service) Verify(ctx, contact string, typ int, code string) error
```

**Send**：SETNX 频率限制（60s 内重复请求报「请求过于频繁」）→ 生成 6 位数字码 → 存 KV（5 分钟）→ `sender.Send`。`LogSender` 用 logx 输出验证码（保留现有 dev 行为）。

**Verify**：读 KV 比对 → 未命中报「验证码已过期」；不匹配则失败计数 +1（达 5 次作废本体），报「验证码错误」；**匹配即 Del 本体与失败计数（一次性消费，防重放）**。

**Redis 适配**：`cache` 包提供 `KV` 的 Redis 实现；Redis 未配置（nil）时 `Send`/`Verify` 明确报「验证码服务不可用」，不再空指针。logic 层一律通过组件访问，禁止直连 `svcCtx.Redis`。

## 四、路径安全（`storage/safe_path.go`）

两层防御，全部在存储层收口：

1. **输入白名单**（进入业务逻辑即校验，非法直接拒绝）：
   - `suffix`：`^[A-Za-z0-9]{1,8}(\.[A-Za-z0-9]{1,8})?$`（兼容 `tar.gz`）
   - `upload_id` / `storage_id`：`^[0-9]{1,32}$`（雪花 ID 形态）
2. **SafeJoin**：`filepath.Join` 后校验结果严格位于 `rootDir` 之内（边界感知前缀检查），越界返回错误。`local_driver.go` 的 `absPath` 与所有路径拼接改走它。

覆盖三条注入路径：`upload_file_logic.go:123` 的 suffix 拼接、`complete_multipart_upload_logic.go:100` 的 FileSuffix、`upload_part/complete/abort` 的 upload_id/StorageID 兜底重建。

## 五、桶配额原子化

1. **大小以服务端为准**：记账一律取 `len(content)`；客户端 `size` 不匹配即拒绝。新增配置 `Storage.MaxUploadSize`（默认 104857600 = 100MB），上传/分片超限直接拒绝不落盘。
2. **单条原子 UPDATE**（repository 新增，ent 自定义谓词表达，不写裸 SQL）：

```sql
UPDATE buckets SET used_size = used_size + ?, version = version + 1
WHERE id = ? AND size_limit >= used_size + ?      -- TryIncUsedSize：0 行 = 配额不足
UPDATE buckets SET used_size = used_size - ?, version = version + 1
WHERE id = ? AND used_size >= ?                   -- TryDecUsedSize：永不为负
```

上传、复制、分片合并三个入口换用；配额不足即拒绝并清理已写物理文件。
3. 删除文件/桶内文件时随删除事务归还配额（TryDecUsedSize）。

## 六、删除事务与存储清理

1. **DeleteFile**（ent.Tx 首次启用）：事务内删 `files` 行 + 级联删该文件 `file_shares` 行 → 提交后清 Redis（分享 meta/counter、`md5:{user}:{md5}` 秒传索引）→ 最后删物理文件（失败仅告警）。
2. **DeleteBucket**：非 force 维持「桶空才能删」，count + delete 包进事务；force 补全 TODO——事务内删桶 + 桶内全部文件行 + 关联分享行，事务后逐文件清理物理文件与 Redis 并记录结果。
3. **驱动清理**：`CompletePart` 合并成功后删除 `.tmp/{uploadID}/`（现在永久残留）；`AbortPart` 同样清理。
4. **complete 前校验分片完整性**：实际分片数 == init 声明的 total_parts，逐片 MD5 与 Redis hash 记录比对，不齐拒绝合并。
5. **错误码**：新增语义归入 `response/codes.go` 现有分段取未用编号——验证码错误 / 过期 / 频率超限 / 服务不可用、路径非法、配额不足、分片不完整、上传体积超限。
