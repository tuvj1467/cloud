## 一、密码加密（bcrypt）

### 1.1 当前状态

[repository/user.go](../cloud/internal/repository/user.go) 中：

```go
// 注册：明文写入
SetPassword(password).   // ← 明文

// 登录：明文比较
if res.Password != in.Password { ... }
```

**风险**：数据库泄露即所有账号暴露，且无法满足合规要求。

### 1.2 改造方案

#### 1.2.1 新增密码工具

新建 `internal/pkg/passwd/passwd.go`：

```go
package passwd

import "golang.org/x/crypto/bcrypt"

// Hash 使用 bcrypt 加密密码（cost=10，约 60ms）
func Hash(plain string) (string, error) {
    bytes, err := bcrypt.GenerateFromPassword([]byte(plain), bcrypt.DefaultCost)
    return string(bytes), err
}

// Compare 校验密码；匹配返回 nil
func Compare(hashed, plain string) error {
    return bcrypt.CompareHashAndPassword([]byte(hashed), []byte(plain))
}
```

#### 1.2.2 改造点

| 文件 | 改动 |
| ---- | ---- |
| `repository/user.go` | `CreateByAccount/Phone/Email`：`SetPassword(passwd.Hash(in.Password))` |
| `repository/user.go` | `LoginByName/Phone/Email`：用 `passwd.Compare` 替换 `!=` |
| `repository/user.go` | `ResetPassword`：`SetPassword(passwd.Hash(in.NewPassword))` |

#### 1.2.3 存量数据兼容

存量用户密码为明文，bcrypt 后无法反向解密。采用**渐进式迁移**：

```go
// LoginByName 改造后的登录逻辑
func (r *UserRepository) LoginByName(ctx, in) (*ent.User, error) {
    res, err := r.client.User.Get(ctx, in.Account)
    if err != nil { ... }

    // 1. 优先用 bcrypt 校验
    if err := passwd.Compare(res.Password, in.Password); err == nil {
        return res, nil
    }

    // 2. 兜底：明文匹配（仅存量数据）
    if res.Password == in.Password {
        // 3. 命中后自动升级为 bcrypt，下次走 bcrypt 分支
        if hashed, err := passwd.Hash(in.Password); err == nil {
            _ = r.client.User.UpdateOneID(res.ID).
                SetPassword(hashed).Exec(ctx)
        }
        return res, nil
    }

    return nil, errors.New("密码或账号错误")
}
```

**优势**：存量用户无感迁移，第一次登录后自动升级；新用户注册即 bcrypt。

#### 1.2.4 验收

- 新注册用户：DB 中 password 字段为 `$2a$10$...` 格式
- 存量明文用户：首次登录后 DB 字段被升级
- 错误密码：返回「密码或账号错误」（不区分账号是否存在，防爆破）

## 二、存量数据迁移

### 2.1 背景

P3 之前，[ent/schema/file.go](../cloud/ent/schema/file.go) 中 `bucket_id` 字段未强制非空，存量 File 记录的 `bucket_id` 可能为空字符串。这些记录会导致：

- `GetBucketFileList` 查询不到
- 容量统计错误
- 删除文件时 `IncUsedSize` 报「桶不存在」

### 2.2 迁移策略

#### 2.2.1 启动时一次性迁移

新建 `internal/pkg/migrate/migrate.go`：

```go
// MigrateFileBucket 启动时检测并迁移 bucket_id 为空的 File 记录
func MigrateFileBucket(ctx, client *ent.Client) error {
    // 1. 查询所有 bucket_id 为空的文件，按 user_id 分组
    files, err := client.File.Query().
        Where(file.BucketIDEqual("")).  // 或 Or(file.BucketIDIsNil())
        All(ctx)
    if err != nil { return err }
    if len(files) == 0 {
        return nil  // 无需迁移
    }

    // 2. 按 user_id 分组
    userFiles := make(map[string][]*ent.File)
    for _, f := range files {
        userFiles[f.UserID] = append(userFiles[f.UserID], f)
    }

    // 3. 每个用户：确保有 default 桶，回填 bucket_id
    for userID, fs := range userFiles {
        bucket, err := ensureDefaultBucket(ctx, client, userID)
        if err != nil { return err }

        var totalSize int64
        for _, f := range fs {
            _, err := client.File.UpdateOneID(f.ID).
                SetBucketID(bucket.ID).Save(ctx)
            if err != nil { return err }
            totalSize += f.Size
        }

        // 4. 累计更新桶已用容量
        _ = client.Bucket.UpdateOneID(bucket.ID).
            AddUsedSize(totalSize).  // 直接加，绕过乐观锁（迁移场景）
            Exec(ctx)
    }
    return nil
}

// ensureDefaultBucket 获取或创建用户的 default 桶
func ensureDefaultBucket(ctx, client, userID) (*ent.Bucket, error) {
    b, err := client.Bucket.Query().
        Where(bucket.UserIDEQ(userID), bucket.NameEQ("default")).
        First(ctx)
    if err == nil { return b, nil }
    if !ent.IsNotFound(err) { return nil, err }

    // 创建默认桶
    return client.Bucket.Create().
        SetID(snowId.MustIdS()).
        SetName("default").
        SetUserID(userID).
        SetSizeLimit(1024 * 1024 * 1024).  // 1GB
        Save(ctx)
}
```

#### 2.2.2 集成到启动流程

在 [main.go](../cloud/main.go) 中 ServiceContext 创建后调用：

```go
ctx := svc.NewServiceContext(c)

// 存量数据迁移（仅 dev 模式自动执行，prod 需手动调用）
if c.Mode == "dev" {
    if err := migrate.MigrateFileBucket(context.Background(), ctx.EntClient); err != nil {
        fmt.Printf("存量数据迁移失败: %v\n", err)
    } else {
        fmt.Println("存量数据迁移完成")
    }
}
```

#### 2.2.3 幂等性

- 查询条件 `bucket_id == ""` 保证只迁移未处理记录
- 重复执行不会重复回填
- `ensureDefaultBucket` 先查后建，已存在则复用

## 三、错误码规范

### 3.1 当前状态

[response.go](../cloud/internal/pkg/response/response.go) 仅 `Success(200)` 与 `Err(500)`，错误信息为字符串拼接，客户端无法精确识别错误类型。

### 3.2 错误码段规划

| 段 | 含义 |
| -- | ---- |
| 10000-10999 | 用户与认证 |
| 20000-20999 | 桶服务 |
| 30000-30999 | 文件服务 |
| 40000-40999 | 存储驱动 |
| 50000-50999 | 系统级（DB/Redis/未知） |

### 3.3 详细错误码

### 3.4 改造 Response

```go
// response.go 扩展
func ErrWithCode(code int32, msg string) (*service.Response, error) {
    return &service.Response{
        Code:    code,
        Message: msg,
        Data:    nil,
    }, nil
}

// 保留 Err 向后兼容（内部用 CodeSystemInternal）
func Err(message error) (*service.Response, error) {
    return ErrWithCode(CodeSystemInternal, message.Error())
}
```

### 3.5 改造调用方

逐步替换各 logic 中的 `response.Err(errors.New("桶不存在"))` 为：

```go
return response.ErrWithCode(response.CodeBucketNotFound, "桶不存在")
```

> 本次改造以**新增常量 + 关键路径替换**为主，避免一次性大改导致回归。其余调用点保留 `Err` 兜底。

## 四、日志补全

### 4.1 当前状态

- 部分 logic 已用 `logx.WithContext(ctx)`（如 `CreateBucketLogic`）
- 关键错误路径仅 `response.Err(err)`，未记录上下文
- 无统一字段（如 user_id / file_id / bucket_id）

### 4.2 改造方案

#### 4.2.1 关键路径加日志

| 路径 | 日志内容 | 级别 |
| ---- | -------- | ---- |
| 上传成功 | `upload success user=%s bucket=%s file=%s size=%d md5=%s` | Info |
| 上传失败 | `upload failed user=%s bucket=%s err=%v` | Error |
| 秒传命中 | `instant hit user=%s md5=%s file=%s` | Info |
| 分片上传完成 | `multipart complete upload_id=%s file=%s parts=%d` | Info |
| 桶容量更新失败 | `bucket capacity update failed bucket=%s err=%v` | Error |
| 分享访问 | `share access code=%s file=%s used=%d/%d` | Info |
| 鉴权失败 | `auth failed method=%s err=%v` | Error |

#### 4.2.2 统一字段约定

使用 `logx.WithContext(ctx)` 自动注入 trace_id，业务字段在 message 中以 `key=value` 形式记录：

```go
l.Infof("upload success user=%s bucket=%s file=%s size=%d md5=%s",
    userID, in.GetBucketId(), fileID, in.GetSize(), md5)
```

#### 4.2.3 启动日志

[main.go](../cloud/main.go) 启动时打印关键组件状态：

```go
fmt.Printf("存储驱动: %s\n", c.Storage.Driver)
fmt.Printf("Redis: %s\n", redisStatus)
fmt.Printf("模式: %s\n", c.Mode)
```

## 七、风险与回滚

1. **bcrypt 性能**：cost=10 单次约 60ms，登录 QPS 受限；可降至 cost=8（约 20ms）平衡安全与性能
2. **存量数据迁移阻塞启动**：迁移量大时启动慢；可通过配置项 `migrate.enabled: false` 跳过，改用独立迁移脚本
3. **错误码改造回归**：客户端若依赖 `code=500` 判断失败，需同步通知；本次保留 `Err` 兜底，仅新增带码 API
4. **日志体积**：Info 日志建议仅记录关键路径，Debug 详情通过 `l.Debugf` 控制
